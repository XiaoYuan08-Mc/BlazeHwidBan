========================================================
BlazeHwidBan 项目 jar 说明（看这个文件就够了）
========================================================

两个 jar 都在本文件夹（D:\插件项目\发布\）。
一句话记法：文件名带【服务器插件】的扔服务器，带【客户端mod】的扔玩家 mods\。

每次更新改了什么，看同文件夹的《更新与补丁报告.txt》（最新在最上面）。
想看项目全貌（功能/原理/命令/构建/部署/检查报告），看《项目报告.md》。
要去 MineBBS 发帖，用《MineBBS发布文案.md》（标题/正文/发布清单都在里面，直接复制）。


--------------------------------------------------------
【服务器插件】BlazeHwidBan-1.1.0-mc26.jar
--------------------------------------------------------
是什么 : 服务器插件（Paper/Bukkit 插件，封禁逻辑全在这里）
放哪里 : 服务器根目录的 plugins\ 文件夹
谁要装 : 只有服务器装。玩家什么都不用装，原版客户端直接进
适用   : Paper 26.x 服务器（Java 25）
状态   : 你的两个测试服都已装好
         - D:\插件项目\test-server\plugins\
         - D:\繁花梦\端\test-server\plugins\


--------------------------------------------------------
【客户端mod】blazehwid-1.0.0-mc26.2.jar
--------------------------------------------------------
是什么 : 客户端模组（Fabric mod）。它不是插件！
         两个功能：①读玩家电脑的真实机器码上报；②上报本机模组
         列表（供黑客端识别）
         1.1.0 无需更新 mod，老 mod 继续用
放哪里 : 玩家电脑 游戏目录\.minecraft\mods\ （启动器里点"打开游戏目录"）
谁要装 : 每个玩家自己装（服务器装了没用，会被无视）
适用   : MC 26.1+ 客户端 + Fabric Loader 0.16+ ，还要再放一个 Fabric API
状态   : 全盘唯一一份原本躺在 D:\繁花梦\端\test-server\plugins\ 里，
         那是放错了地方——服务器不会加载它，需要拷到玩家客户端里


--------------------------------------------------------
2026-09-12 更新 v1.1.0（服务器插件已替换，mod 不变）
--------------------------------------------------------
1. 多服务器封禁同步 (sync)：
   多台服务器共用同一个封禁库，任一服封禁/解封，全部服 5 秒内生效，
   其他服在线的命中玩家会被立即踢出。
   - sync.backend: json=单机文件(默认,行为同旧版) / sqlite / mysql
   - sqlite 适合同一台机器跑多个服；跨机器部署用 mysql
   - 首次启用会自动把本地 bans.json 里的旧封禁迁入库
   - 切换后端需重启服务器；插件首次启动需联网下载 SQL 驱动
   - 指纹档案(profiles.json)不参与同步（每台服指纹盐值不同）
2. 指纹突变告警 (fingerprint-alert)：
   玩家本次进服的客户端指纹与历史都不同时提醒在线管理员
   （改设置/装模组也会变，仅供参考，不自动处罚）。默认开。
3. 同机多账号自动处罚 (alt-auto-action)：
   同一机器码下的不同账号数达到阈值(默认 5)时触发：
   action: alert=仅提醒(默认) / tempban=临时封禁该机器码并踢出
   （tempban 连主号一起封，开之前想清楚）。默认关。
4. 以上新配置项对老安装自动补全，行为默认与 1.0.0 完全一致，
   不改配置就等于没变化。


--------------------------------------------------------
两者的关系（为什么需要两个）
--------------------------------------------------------
服务器插件在服务端拿不到玩家电脑的硬件信息，
所以需要一个客户端 mod 装进玩家电脑里当"线人"读机器码上报，
服务器插件当"法官"记录、比对、封禁。

没装 mod 的玩家照样能进服务器，只是没有机器码、
只剩"客户端指纹"兜底（弱防护，改客户端设置就变）。


--------------------------------------------------------
2026-09-09 更新（两个 jar 均已替换为新版）
--------------------------------------------------------
1. 踢出画面升级为 AdvancedBan 风格：
   被封玩家重进服务器时能看到 玩家名/原因/操作者/
   封禁时间/到期时间/解封标识(机器码前8位) 和封禁类型。
   注意: 如果你服务器里的 config.yml 是老版本,
   messages.kick 模板不会自动覆盖, 想要新画面需手动替换,
   或删掉 messages 整节让它用插件内置默认值。

2. /hwidban unban 现在会同步解除原版封禁：
   以前插件解封了、原版 banned-players.json 里还留着记录,
   玩家照样进不来; 现在两边一起解。
   用 /pardon 解封也依然会联动解除机器码封禁(双向都有)。

3. 反作弊封禁联动机 (anticheat-sync)：
   Grim / Vulcan / Matrix 等反作弊的自动处罚本质是"执行配置的命令",
   本插件直接识别这些封禁命令, 反作弊封谁就跟着封谁的机器码。

   已内置识别(开箱即用):
   - 原版 /ban /pardon
   - LiteBans: /litebans ban|tempban|ipban|unban
   - Vulcan: /vulcan ban
   - Spartan: /spartan ban|tempban|unban
   (Spartan/LiteBans 自建处罚库、不写原版封禁文件, 所以必须显式识别)

   其他反作弊(Grim / Matrix / Intave / NCP ...)的接入方式——
   它们没有固定 ban 命令, 处罚命令由你在它的配置里自定义,
   写成 ban 类即自动联动, 例如:
   - Grim punishments.yml: "ban %player% 作弊" 或 "litebans ban %player%"
   - Intave thresholds: "ban {player} ..." (照官方格式写)
   - Matrix checks.yml 处罚命令: 同理
   还有个更直接的用法: 处罚命令直接写 "hwidban ban %player% 反作弊",
   反作弊一发处罚就直连封机器码, 连命令识别都不用。

   注意: 处罚命令写成 kick 不联动(踢出不等于封禁)。
   防误封: 默认只识别控制台与管理员执行的命令(only-console: true)。
   特别提醒: config 是老版本的服务器升级后, 新增的预置正则不会自动
   出现在旧 config 里(合并只补缺失键), 需手动补进 anticheat-sync 节。

4. 黑客端识别 (client-guard)：拦截外挂客户端加入服务器。
   三道防线 (进服几秒后自动检查):
   ① 客户端品牌(brand)检查 —— 对所有玩家生效:
      品牌命中黑名单正则即拦截 (LiquidBounce/Wurst 等常见外挂端品牌特征),
      正常原版/Fabric 客户端不受影响。
      服务器统一发客户端的话可开 whitelist-mode: true,
      只允许 allowed-brands 里的品牌进 (Lunar/Badlion 也会被拦)。
   ② 违规 Fabric 模组黑名单 —— 依赖玩家装了配套 mod:
      配套 mod 现在会把玩家本机的模组列表一起上报,
      服务器比对 blocked-mods (默认 meteor-client/liquidbounce/wurst 等)。
   ③ require-mod 强制安装配套客户端 —— 最强防护, 默认关:
      开启后没装配套 mod 的玩家进服 8 秒内直接被请出,
      适合"只允许自家客户端进服"的服务器。
   处理动作 client-guard.action: kick=踢出(默认), alert=仅提醒管理员。
   拦截时会给玩家显示"客户端拦截"画面, 同时提醒在线管理员。
   注意事项:
   - config 老版本升级后 client-guard 整节会自动补全(新键才补)。
   - 品牌检查不是万能: 部分外挂端不改品牌, 靠②③层拦。
   - 客户端上报的内容理论上可被篡改, ②③是提高门槛, 不是绝对防线;
     配合反作弊行为检测(anticheat-sync 联动)才是完整纵深。
