🛡️ BlazeHwidBan —— 封的是设备，不是账号。

换小号 ✕　换客户端 ✕　换 IP ✕
传统封禁玩家注册个小号一键回到服务器，本插件把封禁下沉到设备层：原版玩家靠客户端指纹识别，装了配套模组的玩家靠真实机器码识别，同时拦截外挂客户端进服，并联动反作弊与原版封禁系统。

- 适用服务端：Paper 26.x（Java 25）
- 配套模组：Fabric（MC 26.1+ 客户端，需 Fabric API，玩家可选装）
- 开源协议：MIT，源码完全公开可自行审查
- 下载：https://github.com/XiaoYuan08-Mc/BlazeHwidBan/releases

【💡 为什么需要它】

传统封禁 vs BlazeHwidBan：

- 封禁对象：玩家名 / UUID → 这台电脑
- 换小号：失效 → 无效
- 换客户端：失效 → 无效
- 原版玩家：可封 → 可封（指纹识别）
- 与反作弊联动：手动 → 自动

服务端拿不到玩家硬件信息，客户端也拿不到封禁库，所以需要两端配合：一个服务端插件 + 一个客户端模组。只装服务端插件也能用（指纹兜底），玩家装了模组防护升级为真实机器码。

【✨ 功能一览】

🔒 封禁核心
- 机器码封禁（设备级，换号/换客户端均无效）
- 客户端指纹兜底（原版玩家也能被识别）
- 临时封禁（7d12h 时长可组合，到期自动解除）
- 封禁生效自动踢出同机在线账号
- 同机新账号进服自动提醒在线管理员

🔗 智能联动
- 反作弊联动：LiteBans / Vulcan / Spartan 开箱即用，Grim / Matrix / Intave 自定义即生效
- 原生 /ban、/pardon 双向同步（启动时自动转换既有原版封禁）
- 外挂客户端识别（品牌 + 模组双重检查）

⚙️ 服务器友好
- 配置自动合并（升级只补缺失键，自定义与盐值不受影响）
- 审计日志 · AdvancedBan 风格封禁画面 · 豁免权限
- 全部文案可自定义（MiniMessage 富文本，40+ 消息键）

【🔍 工作原理】

两种身份标识：

① 真实机器码（强标识）—— 玩家电脑 OS 级稳定标识，在本机计算 SHA-256，只把哈希发给服务器，原始硬件信息不出玩家电脑。装了配套模组的玩家才有。

② 客户端指纹（弱标识）—— 品牌 + 语言 + 设置 + 频道 → 加盐哈希，所有玩家都有（含原版客户端）。改客户端设置会变化，仅作兜底。

玩家进服的判定流程：

1. 读客户端品牌 → 命中外挂端黑名单 → 🚫 拦截
2. 收到模组上报（机器码 + 模组列表）→ 模组在黑名单拦截；机器码在封禁库踢出并显示封禁画面
3. 未装模组（宽限 5~8 秒）→ require-mod 开启则拒绝进入，否则用指纹兜底判定
4. ✅ 放行 → 同机关联检查 → 命中则提醒在线管理员

反作弊联动原理：各反作弊的事件 API 不统一，但它们的"自动处罚"本质都是执行一条命令，所以本插件监听命令——反作弊判定作弊 → 执行它配置的 ban 命令 → 本插件识别 → 补封机器码 → 踢出同机账号。只需把反作弊的处罚命令写成 ban 类（写成 kick 不会联动，踢出 ≠ 封禁，避免误伤）。

【🚀 快速开始】

1️⃣ 服务端安装
下载 BlazeHwidBan-1.0.0-mc26.jar，放进服务器 plugins/ 文件夹，重启即可（要求 Paper 26.x + Java 25，配置文件自动生成）。

2️⃣ 玩家端安装（可选，但强烈建议）
装了才能识别真实机器码（否则只能用指纹兜底）：
- 下载 blazehwid-1.0.0-mc26.2.jar，放进 .minecraft/mods/ 文件夹
- 同时需要 Fabric API：https://modrinth.com/mod/fabric-api
玩家端不是必须的 —— 不装模组的玩家一样能被指纹识别与封禁。

3️⃣ 开始使用

/hwidban ban 玩家名 使用外挂　（封禁，自动联动封机器码）
/hwidban alt 玩家名　　　　　　（查这个人的其他小号）
/hwidban list　　　　　　　　　（查看封禁列表）

【📜 指令与权限】

主命令 /hwidban（别名 /hban）· 权限 hwidban.admin（默认仅 OP）

- /hwidban ban <玩家> [理由] —— 封禁玩家（联动封其全部机器码与指纹）
- /hwidban tempban <玩家> <时长> [理由] —— 临时封禁，时长可组合如 1d12h
- /hwidban banhwid <64位机器码> [理由] —— 直接封一个机器码
- /hwidban unban <机器码前缀|玩家名> —— 解封（同步解除原版封禁）
- /hwidban check <玩家> —— 查看该玩家的机器码档案与状态
- /hwidban alt <玩家> —— 同机账号情报（同一台电脑上的其他账号）
- /hwidban list [页码] —— 封禁列表分页
- /hwidban info —— 插件状态概览
- /hwidban reload —— 重载配置文件

权限：
- hwidban.admin —— 全部管理指令（默认 OP）
- hwidban.exempt —— 豁免机器码/指纹校验（默认无人拥有，需手动授予）

【🔗 反作弊配置示例】

内置识别（开箱即用，无需配置）：
- 原版 /ban /pardon
- LiteBans：ban / tempban / ipban / unban
- Vulcan：/vulcan ban
- Spartan：/spartan ban / tempban / unban

Grim / Matrix / Intave / NCP（处罚命令由管理员自定义），在 Grim 的 punishments.yml 里写：

ban %player% 作弊

也可以直连封机器码：

hwidban ban %player% 反作弊判定

【❓ 常见问题】

Q：玩家不装模组能被封吗？
A：能。不装模组的玩家用客户端指纹识别（弱标识，但足以拦住多数换号行为）；装了模组则是真实机器码（强标识，换号无效）。

Q：会误封网吧 / 共用电脑吗？
A：默认不会。只有开启 strict-mode（一台机器绑定首个账号）才可能，该模式默认关闭。

Q：模组会泄露我的硬件信息吗？
A：不会。模组只在本机计算 SHA-256 哈希，服务器收到的是一串哈希值，原始硬件信息不出你的电脑。源码完全公开，可自行审查。

Q：和反作弊插件冲突吗？
A：不冲突。反作弊负责检测，本插件负责把封禁落到设备层，两者互补。

Q：plugin.yml 里写的 api-version: '1.21' 是不是支持 1.21？
A：不是。那是 Paper 规定的最低 API 等级声明（固定值），本插件只支持 Paper 26.x 服务端。

【⚠️ 诚实说明】

本插件不吹"绝对防不住"，以下是已知边界：

- 客户端上报内容理论上可被篡改 —— 品牌与模组检查是提高门槛，不是绝对防线；配合反作弊行为检测才是完整纵深。
- 部分外挂端不改品牌标识 —— 此时靠模组黑名单与机器码兜底。
- 指纹是弱标识 —— 玩家修改客户端设置会变化，仅用于原版玩家兜底。
